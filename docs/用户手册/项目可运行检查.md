# 项目可运行检查

先按终端中最早出现的错误定位。后续错误通常只是前一个问题的连锁结果。

运行：

```bash
python -m stiffness_agent validate-project
```

## macOS/Clang 验证后实现矩阵显示为已修改

内置 S4 验证会重新生成样本元数据指定的
`data/implementation/*.csv` 实现矩阵。不同编译器或平台可能只在浮点数的
最后几位产生文本差异，因此 macOS 使用 `clang++` 完成验证后，
`git status --short` 可能列出这些文件。

先检查差异：

```bash
git diff -- data/implementation
```

如果验证前工作树是干净的，并且确认差异只来自本次验证生成的实现矩阵，
可以恢复仓库中的版本：

```bash
git restore -- data/implementation
```

如果验证前已有本地修改，应逐文件保留和处理，不能直接恢复整个目录。
`data/implementation/` 是实现输出；`data/reference/abaqus/matrices/` 是
可信参考矩阵，两者不能互换，也不要为消除跨平台末位差异而修改参考矩阵。



## 在线多智能体命令失败

`validate-project`、`check`、`verify` 和 `verify-dataset` 不需要在线模型。先让这些离线命令通过，再检查在线部分：

```bash
python -m stiffness_agent api-check
```

确认 `.env` 中的接口地址、模型名和密钥有效。`.env` 只保留在本机，不能提交到 Git。

## 哪些输出可以重建

可以删除并重新生成：`build/`、`__pycache__/` 和 `*.pyc`。

谨慎删除：`build/workflow/checkpoints/`、`build/workflow/runs/`、`build/workflow/archive/` 和 `build/workflow/plans/`，因为它们包含恢复状态或审计历史。

不要把参考矩阵、样本元数据或来源证据当作缓存删除。Abaqus 临时文件只有在 `.mtx`、CSV 和必要日志已经归档后才清理。
