# 多智能体角色定义

本文档说明在线智能体负责什么、提示词放在哪里，以及哪些结论必须由本地程序验证。智能体不能自行宣称编译、测试或数值验收通过。

## 1. 数值优化角色

| 角色 | 提示词 | 职责 |
| --- | --- | --- |
| 实验规划智能体 | `stiffness_agent/prompts/workflow/planner.*.md` | 根据训练集诊断和实验记忆选择一个修改方向 |
| 理论研究智能体 | `stiffness_agent/prompts/workflow/theory.*.md` | 解释规划范围内的理论机理和风险 |
| 开发智能体 | `stiffness_agent/prompts/workflow/developer.*.md` | 为允许的 C++ 文件生成受限统一差异补丁 |
| 评审智能体 | `stiffness_agent/prompts/workflow/reviewer.*.md` | 根据候选前后的验证事实提出接受或拒绝建议 |

规划智能体必须输出结构化 JSON，包含实验类别、目标分块、唯一主指标、允许修改项、禁止修改项和预期变化。理论、开发和评审智能体都必须遵守同一份计划。

## 2. 数据生成角色

| 角色 | 提示词 | 职责 |
| --- | --- | --- |
| 数据集规划智能体 | `stiffness_agent/prompts/dataset/planner.system.md` | 设计样本几何、参数和数据划分 |
| Abaqus 数据智能体 | `stiffness_agent/prompts/dataset/data-agent.system.md` | 按批准计划生成输入并调用真实 Abaqus |
| 数据集校验智能体 | `stiffness_agent/prompts/dataset/validator.system.md` | 检查日志、元数据、矩阵尺寸和来源证据 |

数据计划必须先通过 `validate-data-plan`，真实产物必须通过 `register-sample`，锁定测试集还必须通过哈希校验。

## 3. 确定性工具节点

Coordinator 和 Test 不依赖模型自由判断，而由 Python 程序和本地命令实现：

- Coordinator 创建运行目录、维护状态并依次调度各角色。
- Test 配置和编译 C++、运行 Catch2、重新生成实现矩阵并计算误差。
- 本地门禁检查补丁范围、主指标改善、非目标分块退化、验证集退化和重复补丁。
- 只有本地门禁与评审建议都允许时，候选实现才会保留。

## 4. 提示词维护

提示词源文件全部位于 `stiffness_agent/prompts/`：

```text
stiffness_agent/prompts/
├── workflow/
│   ├── planner.system.md
│   ├── planner.user.md
│   ├── theory.system.md
│   ├── theory.user.md
│   ├── developer.system.md
│   ├── developer.user.md
│   ├── reviewer.system.md
│   └── reviewer.user.md
└── dataset/
    ├── planner.system.md
    ├── data-agent.system.md
    └── validator.system.md
```

`.system.md` 定义长期角色约束，`.user.md` 是每轮填充运行上下文的模板。提示词可以改变模型如何分析和表达，但不能绕过本地测试与门禁。

API 地址、模型名称和密钥通过 `.env` 或环境变量配置，不写进提示词。密钥只保存在本机，仓库仅提交 `.env.example`。

## 5. 运行产物

每次在线数值迭代写入：

```text
build/workflow/
├── latest-report.md
├── progress-log.md
├── experiment-memory.json
└── runs/<运行编号>/
    ├── state.json
    ├── summary.md
    └── iteration-XX/
        ├── experiment-plan.json
        ├── theory-analysis.md
        ├── developer.patch
        ├── verification-candidate.log
        └── reviewer-response.md
```

这些文件是可再生成的本地运行记录，已经由 `.gitignore` 排除。长期、可复验的数值结论才写入 `docs/verification/`。
