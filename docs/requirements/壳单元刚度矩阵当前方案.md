# 壳单元刚度矩阵优化与多 Agent 协作方案

整理日期：2026-07-07

## 1. 任务目标

本任务目标是以多 agent 协作形式完成壳单元刚度矩阵优化，形成可运行、可测试、可对标的技术交付。

最终希望实现：

- 使用 Abaqus 生成若干四节点壳单元的 24 x 24 单元刚度矩阵，作为基准数据。
- 基于 C++ 实现壳单元单刚计算和矩阵组装逻辑。
- 使用 Catch2 编写单元测试和对标测试。
- 验证 C++ 输出的单元刚度矩阵与 Abaqus 给出的单刚误差控制在 1% 以内。
- 输出多 agent 协同方案，包括角色定义、任务分工、数据交接和验收标准。

## 2. 当前已有基础

项目参考资料中已有两类可复用材料。

第一类是理论资料：

- ANSYS SHELL181 调研文档。
- Shell181 代码实现说明。
- Shell181 应力恢复与刚度矩阵推导资料。

第二类是已有代码：

- Shell203 壳单元参考实现。
- Shell203 对应 Catch2 测试。
- 两组已有 24 x 24 单元刚度矩阵基准数据。

其中 Shell203 参考代码明确说明：一阶对标 ANSYS SHELL181，二阶对标 ANSYS SHELL281。代码中已经包含四节点壳单元刚度矩阵组装、MITC 剪切独立插值、位移不相容模式、drill 自由度罚刚度和基础测试。因此当前方案不建议从零开始写壳单元，而是以 Shell203 参考实现为基础，整理成一个可独立验证的 C++ 原型。

## 3. 当前推荐技术路线

### 3.1 先完成口径对齐

在正式开发前，先和老师确认 Abaqus 基准数据的生成口径。因为壳单元刚度矩阵对单元类型、积分方式、自由度顺序、局部坐标和 drill 刚度都很敏感。如果这些口径不统一，即使代码正确，误差也可能超过 1%。

当前建议先确认：

- Abaqus 使用的壳单元类型：优先讨论 `S4` 或 `S4R`。
- 每个节点自由度顺序：建议统一为 `Ux Uy Uz Rx Ry Rz`。
- 四节点顺序：建议统一为逆时针顺序。
- 厚度方向积分点：建议第一版使用 3 点。
- 误差指标：建议主指标用 Frobenius 相对误差小于 1%。
- 样本数量：建议先用 2 个样本跑通，再扩展到 10 个，最终可扩展到 100 个。

### 3.2 再搭建 C++ 最小原型

第一版 C++ 不做完整有限元软件，只做单元级刚度矩阵计算。

建议最小接口为：

```cpp
Matrix24 computeS4Stiffness(const S4ElementInput& input);
Matrix24 readAbaqusMatrix(const std::filesystem::path& path);
MatrixError compareMatrix(const Matrix24& actual, const Matrix24& expected);
```

输入包括：

- 4 个节点坐标。
- 材料参数 `E`、`nu`。
- 壳厚度。
- 积分点设置。
- 可选局部坐标或法向信息。

输出为：

- C++ 计算得到的 24 x 24 单元刚度矩阵。
- 与 Abaqus 基准矩阵的误差指标。

### 3.3 再接入 Abaqus 基准数据

Abaqus 数据建议统一保存为：

```text
data/reference/abaqus/input_decks/
data/reference/abaqus/matrices/
data/reference/abaqus/metadata/
```

每个样本需要保存：

- Abaqus 输入文件或关键建模参数。
- 节点坐标。
- 节点顺序。
- 材料参数。
- 厚度。
- 单元类型。
- 24 x 24 单刚矩阵。
- 自由度顺序说明。

这样 C++ 测试可以直接读取矩阵文件和元数据，自动完成对比。

### 3.4 最后用 Catch2 做验收测试

测试分三层：

- 基础测试：矩阵维度、对称性、非法输入。
- 回归测试：复用现有 Shell203 的两组 24 x 24 基准矩阵，确保参考逻辑迁移后不变。
- Abaqus 对标测试：读取 Abaqus 导出的单刚，验证误差小于 1%。

## 4. 多 agent 协作方案

当前建议定义 4 个主要角色。

### 4.1 理论研究 Agent

职责：

- 阅读 ANSYS SHELL181 和 Shell181 实现资料。
- 梳理自由度、形函数、积分、剪切修正、drill 刚度和坐标变换。
- 标注 Shell203 代码与理论公式的对应关系。
- 记录 Abaqus 和 ANSYS 壳单元可能存在的差异。

输出：

- 理论说明文档。
- 实现映射文档。
- 误差来源清单。

### 4.2 Abaqus 数据 Agent

职责：

- 生成 Abaqus 壳单元算例。
- 导出每个单元的 24 x 24 单刚。
- 固化数据格式、自由度顺序和样本元数据。

输出：

- Abaqus 输入文件。
- 单刚矩阵文件。
- 样本元数据。

### 4.3 C++ 开发 Agent

职责：

- 基于 Shell203 参考实现整理 C++ 原型。
- 实现单刚计算接口。
- 实现 Abaqus 矩阵读取和误差计算。

输出：

- C++ 源码。
- 头文件和接口说明。
- 示例输入输出。

### 4.4 测试 Agent

职责：

- 使用 Catch2 编写测试。
- 做矩阵性质检查。
- 做 Shell203 回归测试。
- 做 Abaqus 对标误差测试。

输出：

- Catch2 测试代码。
- 测试报告。
- 误差统计表。

## 5. 当前默认方案

如果老师没有特殊要求，建议先按下面默认口径推进第一版：

- Abaqus 样本数量：先做 2 个，后续扩展到 10 或 100。
- Abaqus 单元类型：先和老师确认 `S4` / `S4R`，未确认前不锁死。
- C++ 实现：以 Shell203 参考实现为基础，整理成最小可编译原型。
- 每节点自由度：`Ux Uy Uz Rx Ry Rz`。
- 矩阵大小：4 节点 x 6 自由度 = 24 x 24。
- 厚度方向积分点：默认 3 点。
- 误差主指标：Frobenius 相对误差小于 1%。
- 测试工具：Catch2。
- 交付形式：源码、测试、README、多 agent 协同方案、误差报告。

## 6. 需要老师确认的问题

建议和老师重点确认以下问题：

1. Abaqus 基准单元使用 `S4` 还是 `S4R`。
2. 最终样本数量 X 是多少，是否按 100 个作为最终目标。
3. Abaqus 单刚矩阵希望用什么方式导出，CSV 是否可接受。
4. 误差 1% 是按 Frobenius 相对误差，还是要求矩阵每一项都小于 1%。
5. C++ 是否必须做成完全独立工程，还是允许复用现有 BEF 框架。
6. 第 6 个转角自由度的 drill stiffness 是否纳入严格对标。
7. 是否需要显式指定壳单元局部坐标或法向。

## 7. 如果老师认可，下一步计划

如果老师认可当前方案，后续按以下顺序推进：

### 第一步：整理项目结构

建立 C++ 工程目录、文档目录、测试目录和 Abaqus 数据目录。

### 第二步：整理 Shell203 最小实现

从参考代码中抽取单刚计算所需的最小代码，先保证能够输出 24 x 24 矩阵。

### 第三步：接入 Catch2 回归测试

先用已有的两组 24 x 24 参考矩阵做回归测试，保证整理后的实现没有偏离现有参考代码。

### 第四步：生成 Abaqus 小样本

先生成 2 个 Abaqus 壳单元样本：一个平面单元，一个斜平面或扭曲单元。

### 第五步：做 Abaqus 对标

读取 Abaqus 单刚矩阵，计算 C++ 与 Abaqus 的误差。如果误差超过 1%，优先排查自由度顺序、节点顺序、局部坐标、drill 刚度和积分设置。

### 第六步：扩展到 X 个样本

小样本通过后，再扩展到最终样本数量，并输出误差统计报告。

## 8. 当前判断

当前任务的关键不在于“多 agent”本身，而在于先把壳单元刚度矩阵的技术口径对齐。多 agent 应作为协同组织方式，服务于理论、代码、数据和测试之间的交接。

因此建议汇报时强调：

- 已有参考资料和 Shell203 代码可以作为技术基础。
- 第一阶段重点是确认 Abaqus 对标口径。
- 第二阶段才是整理 C++ 原型和 Catch2 测试。
- 最终用 Abaqus 基准矩阵证明误差是否满足 1%。
