# 通用单元刚度矩阵工作流用户手册

这是一份完整的操作手册。第一次运行、增加样本、接入新单元、配置模型、查看结果和排查问题都在本页，不需要再到多个用户文档之间来回查找。

## 1. 这个项目做什么

项目比较两份单元刚度矩阵：

- **参考矩阵**：来自 Abaqus 或其他可信求解器，作为对照答案；
- **实现矩阵**：由正在开发的 C++ 或其他程序计算，是需要改进的结果。

工作流会检查矩阵尺寸、有限性和对称性，计算误差，运行测试，并把多个样本分成训练集、验证集和最终测试集。在线多智能体可以规划实验、分析理论、提出代码补丁和评审结果，但是否通过始终由本地编译、测试和数值门禁决定。

仓库当前内置的是 Abaqus S4 示例：4 个节点，每节点 6 个自由度，输出 `24 x 24` 刚度矩阵。公共验证流程也支持其他尺寸，但新单元必须有自己的矩阵计算程序。

## 2. 第一次运行

### 环境要求

- Python 3.10 或更高版本；
- 能以 `c++` 命令调用的 C++17 编译器；
- 仓库根目录是当前终端目录；
- 离线验证不需要模型 API；
- 只有重新生成 S4 参考矩阵时才需要 Abaqus。

Windows 没有 `c++` 命令时，可以安装 MinGW 或 LLVM 并设置 `CXX`，也可以在 WSL 中运行。当前项目已使用 WSL Ubuntu GCC 13.3 验证通过。

安装 Python 依赖：

```bash
python -m pip install -r requirements.txt
```

检查项目配置和 Python 环境：

```bash
python -m stiffness_agent check
```

验证主样本：

```bash
python -m stiffness_agent verify \
  --sample data/reference/abaqus/metadata/sample_001.json \
  --report build/verification/sample_001-report.md
```

PowerShell 可以写成一行：

```powershell
python -m stiffness_agent verify --sample data/reference/abaqus/metadata/sample_001.json --report build/verification/sample_001-report.md
```

验证开发数据集：

```bash
python -m stiffness_agent verify-dataset --development
```

成功时应看到 `Element matrix verification completed` 或 `Dataset verification completed`，并且对应的 C++ 测试通过。

## 3. 输入、输出和常用文件

### 必需输入

| 输入 | 作用 |
| --- | --- |
| `stiffness_agent/config/project.json` | 声明单元、矩阵尺寸、数据集、计算程序和验收门槛 |
| 样本元数据 JSON | 保存一个算例的几何、材料、自由度和文件路径 |
| 参考矩阵 CSV | 可信求解器导出的对照矩阵 |
| 矩阵计算程序 | 根据样本生成实现矩阵 |
| 数据集清单 | 把样本登记到 `train`、`validation` 或 `test` |

### 主要输出

| 输出 | 默认位置 |
| --- | --- |
| 实现矩阵 | 样本 JSON 的 `implementation_matrix` 字段指定的位置 |
| 单样本报告 | `verify --report` 指定的位置 |
| 数据集结果 | `build/verification/dataset-results.json` |
| 每个样本的临时报告 | `build/verification/dataset-reports/<split>/` |
| 在线迭代记录 | `build/workflow/` |

`build/` 是可重新生成的本地输出，不应手工维护或提交。

### 项目配置中最常改的字段

| 字段 | 含义 |
| --- | --- |
| `project_id` | 项目稳定标识，必须与数据集一致 |
| `element_type` | 单元类型，必须与样本一致 |
| `matrix_dimensions` | 方阵尺寸，例如 `[24, 24]` |
| `node_count` | 节点数 |
| `dof_labels_per_node` | 每节点自由度顺序 |
| `diagnostic_groups` | 把自由度分成膜、弯曲等诊断组 |
| `dataset` | 数据集清单路径 |
| `primary_sample` | 不指定 `--sample` 时使用的样本 |
| `adapter` | 工作流如何调用矩阵计算程序 |
| `agent.allowed_patch_paths` | 开发智能体允许修改的源码 |
| `acceptance` | 目标误差和允许的回归幅度 |

非 S4 配置可以从 `stiffness_agent/config/project.example.json` 复制。

### 样本元数据最小结构

```json
{
  "sample_id": "train_001",
  "element_type": "MY_ELEMENT",
  "parameters": {},
  "reference_matrix_source": {
    "status": "verified_external_reference",
    "solver": "可信参考求解器",
    "job": "作业编号"
  },
  "reference_matrix": "data/my_element/reference/train_001.csv",
  "implementation_matrix": "data/my_element/implementation/train_001.csv"
}
```

`parameters` 由具体单元程序解释，可以包含节点、材料、厚度、截面或积分参数。`reference_matrix_source.status` 使用 `real_abaqus_export` 或 `verified_external_reference`，不能把实现程序生成的矩阵登记成参考矩阵。

矩阵 CSV 不带表头，所有条目必须是有限数值，并满足：

```text
矩阵阶数 = 节点数 x 每节点自由度数
```

## 4. 给现有单元增加样本

以当前 S4 为例，按下面顺序操作：

1. 创建新的 Abaqus `.inp`，不要覆盖原有样本。
2. 运行真实 Abaqus，使用 `*MATRIX GENERATE` 导出矩阵。
3. 保存必要的原始 `.mtx` 和作业日志。
4. 将 `.mtx` 转换为方阵 CSV，并检查尺寸、有限性和对称性。
5. 创建样本元数据 JSON，记录作业名、求解器版本、导出方式和文件路径。
6. 登记到数据集。
7. 运行单样本和开发数据集验证。

登记训练样本：

```bash
python -m stiffness_agent register-sample \
  --meta data/reference/abaqus/metadata/<sample_id>.json \
  --split train
```

`--split` 可以是 `train`、`validation` 或 `test`。登记测试样本会重建测试集哈希锁。S4 的 Abaqus 输入和矩阵转换命令见 `docs/abaqus/导出S4刚度矩阵.md`。

## 5. 接入其他单元或其他矩阵尺寸

公共工作流不负责猜测新单元公式。接入梁、实体或其他单元时，需要准备：

1. 新单元的节点数、自由度顺序和矩阵尺寸；
2. 一个读取样本 JSON、写出实现矩阵 CSV 的程序；
3. 至少一个来自可信求解器的参考样本；
4. 新的数据集清单；
5. 新单元自己的数值测试。

推荐把实现和数据放在独立目录，例如：

```text
elements/beam2/                 新单元实现和测试
data/beam2/metadata/            样本 JSON
data/beam2/reference/           可信参考矩阵
data/beam2/implementation/      实现矩阵
data/datasets/beam2.json        数据集清单
```

### `command` 适配器是什么

它不是一种有限元算法，只是告诉工作流应该执行哪几个终端命令：

```json
"adapter": {
  "kind": "command",
  "build_command": ["cmake", "--build", "build"],
  "evaluate_command": ["build/my_element_cli", "{sample}"],
  "test_command": ["ctest", "--test-dir", "build", "--output-on-failure"]
}
```

- `build_command`：编译你的程序；
- `evaluate_command`：把 `{sample}` 替换为样本 JSON 路径并生成实现矩阵；
- `test_command`：运行该单元自己的测试。

矩阵程序只需要遵守一个约定：读取命令行中的样本 JSON，把结果写到 JSON 的 `implementation_matrix` 路径。工作流随后读取参考矩阵和实现矩阵并生成报告。

完成配置后运行：

```bash
python -m stiffness_agent validate-project
python -m stiffness_agent verify --sample <样本.json> --report build/verification/<报告>.md
python -m stiffness_agent verify-dataset --development
```

## 6. 数据集如何使用

| 划分 | 用途 | 开发时是否读取 |
| --- | --- | --- |
| `train` | 提供详细误差，支持算法调整 | 是 |
| `validation` | 防止只适配训练样本 | 是 |
| `test` | 最终独立验收 | 否 |

三个划分必须互不重叠。开发阶段使用：

```bash
python -m stiffness_agent verify-dataset --development
```

只有测试集已登记并且哈希锁有效时，才运行最终验收：

```bash
python -m stiffness_agent verify-dataset --require-test
```

## 7. 配置模型 API 并运行智能体

从示例创建本机配置：

```powershell
Copy-Item .env.example .env
```

主要字段：

| 字段 | 作用 |
| --- | --- |
| `OPENAI_API_KEY` | API 密钥 |
| `OPENAI_MODEL` | 所有在线智能体默认使用的模型 |
| `OPENAI_BASE_URL` | OpenAI 或兼容网关地址，通常以 `/v1` 结尾 |
| `OPENAI_API_STYLE` | `auto`、`responses` 或 `chat_completions` |
| `OPENAI_TIMEOUT_SECONDS` | 单次请求超时 |
| `OPENAI_MAX_RETRIES` | 临时错误重试次数 |
| `OPENAI_REASONING_EFFORT` | 模型推理强度 |

`.env` 只保存在本机，禁止提交。先测试接口：

```bash
python -m stiffness_agent api-check
```

启动在线迭代：

```bash
python -m stiffness_agent run --max-iterations 3
```

切换单元、数据集或算法方向时重新建立规划代次：

```bash
python -m stiffness_agent reset-plan --reason "说明新目标"
python -m stiffness_agent replan
```

接口中断后可以从检查点恢复：

```bash
python -m stiffness_agent resume <运行编号>
```

每轮记录写入 `build/workflow/runs/<运行编号>/`，不会进入 Git。

## 8. 如何阅读结果

| 指标 | 含义 |
| --- | --- |
| `frobenius_relative_error` | 整体矩阵相对误差，当前主指标 |
| `max_absolute_error` | 单个矩阵条目的最大绝对差 |
| `max_relative_entry_error` | 逐项最大相对差，容易被接近零的参考条目放大 |
| `symmetry_error` | 实现矩阵相对自身转置的不对称程度 |
| `<group>__<group>` | 项目配置中诊断分组之间的误差 |

流程通过只说明程序可运行、测试没有失败，不等于数值误差已经达到目标。最终结论应看独立测试集的最差误差，而不是只看训练集平均值。

## 9. 常见问题

### 找不到 `c++`

安装支持 C++17 的 GCC 或 Clang，并确保终端能运行 `c++ --version`。Windows 也可以在 WSL 中进入仓库后运行验证。

### 在线命令失败

`validate-project`、`check`、`verify` 和 `verify-dataset` 都不需要模型 API。先让这些命令通过，再运行 `python -m stiffness_agent api-check` 检查 `.env` 中的地址、模型和密钥。

### macOS 验证后实现矩阵显示为修改

不同编译器可能只在浮点数最后几位产生文本差异。先运行：

```bash
git diff -- data/implementation
```

确认验证前工作树干净且差异只来自本次生成后，可以恢复实现矩阵：

```bash
git restore -- data/implementation
```

不要修改或恢复 `data/reference/abaqus/matrices/` 中的可信参考矩阵。如果验证前已有本地修改，应逐文件处理，不能直接恢复整个目录。

### 哪些文件可以删除

- 可以重建：`build/`、`__pycache__/`、`*.pyc`；
- 谨慎删除：`build/workflow/checkpoints/`、`runs/`、`archive/` 和 `plans/`，删除后会丢失恢复状态或审计记录；
- 不要随意删除：参考矩阵、样本元数据、数据集清单和来源证据；
- Abaqus 临时文件只有在原始矩阵、CSV 和必要日志已经归档后才清理。

## 10. 为什么这样组织

项目分成三层：

1. **用户数据层**保存项目配置、样本、参考矩阵和数据集；
2. **矩阵计算层**实现具体单元公式，把一个样本转换成实现矩阵；
3. **公共验证与编排层**负责矩阵比较、数据隔离、智能体门禁、回退和审计。

不同单元的公式和尺寸不同，但验证过程始终是：

```text
样本 -> 实现矩阵 -> 与参考矩阵比较 -> 运行测试 -> 生成报告
```

因此新单元应提供自己的矩阵计算程序，不要把 S4 公式硬改成所谓的通用公式。Planner、Theory、Developer 和 Reviewer 可以提出改进，但可信参考矩阵、测试结果和接受门槛不能由模型修改或绕过。

本手册已经覆盖普通用户所需操作。只有需要重新导出 Abaqus 数据、研究 S4 理论、修改智能体角色或核对正式数值结果时，才查看 `docs/abaqus/`、`docs/requirements/`、`docs/agents/` 和 `docs/verification/`。
