# 通用单元矩阵工作流用户手册

## 项目介绍

本项目是一个面向有限元单元刚度矩阵开发的多智能体协作框架。它把一次算法改进拆分为规划、理论分析、代码修改、结果审查和经验记录，让多个智能体围绕同一个数值目标连续协作。

规划智能体选择本轮改进方向，理论智能体解释误差原因，开发智能体在限定范围内修改代码，审查智能体根据矩阵误差决定是否接受本轮结果。每轮结论都会保存，供下一轮继续使用。

```text
项目目标、样本和参考矩阵（参考商软计算的矩阵）
              ↓
规划智能体选择本轮改进方向
              ↓
理论智能体分析误差原因
              ↓
开发智能体修改矩阵计算程序
              ↓
审查智能体比较结果并决定接受或拒绝
              ↓
保存本轮经验，进入下一轮
```

仓库当前使用 Abaqus S4 四节点壳单元作为首个多智能体改进示例，每节点有 6 个自由度，输出 `24 x 24` 刚度矩阵。

框架也可以用于其他节点数、自由度和矩阵尺寸的单元，但需要为新单元准备对应的计算程序、样本和参考矩阵。

本手册只介绍整体流程。算法推导和多智能体内部实现放在独立说明中。

## 项目目录

```text
Kagent/
├── stiffness_agent/    命令行、项目配置和智能体提示词
├── scripts/        多智能体编排、模型调用和 Abaqus 工具
├── data/           样本、参考矩阵和实现矩阵
├── src/            C++ 单元程序源码
├── include/        C++ 头文件
├── tests/          自动检查代码
├── docs/           用户手册、技术说明和验证报告
├── build/          编译结果和本次运行生成的报告
├── CMakeLists.txt  C++ 工程构建入口
├── requirements.txt  Python 工作流依赖
├── .env.example    在线接口配置示例
└── README.md       项目入口说明
```

| 目录或文件 | 主要内容 | 普通用户什么时候会用到 |
| --- | --- | --- |
| `scripts/` | 多智能体图编排、模型接口和辅助脚本 | 启动或调整多智能体流程时 |
| `stiffness_agent/` | 命令入口、项目配置、公共验证逻辑和智能体提示词 | 从终端操作或配置项目时 |
| `data/` | 样本 JSON、Abaqus 原始文件、可信参考矩阵和实现矩阵 | 新增或检查样本时 |
| `src/`、`include/` | 当前 S4 刚度矩阵的 C++ 实现 | 修改单元计算公式时 |
| `tests/` | 项目行为和数值规则的自动检查代码 | 通常不直接修改 |
| `docs/` | 用户操作、Abaqus 导出步骤、理论和验证记录 | 查阅用法和结果时 |
| `build/` | 编译产物以及 `build/verification/` 下的验证报告 | 查看本次运行结果时 |
| `CMakeLists.txt` | C++ 程序和 Catch2 测试的构建规则 | 编译或增加 C++ 代码时 |
| `requirements.txt` | Python 工作流依赖列表 | 创建运行环境时 |
| `.env.example` | 在线模型接口的配置示例，不包含真实密钥 | 配置多智能体运行时 |
| `README.md` | 项目入口、环境安装和常用命令 | 第一次打开仓库时 |

本项目的核心是 `stiffness_agent/` 和 `scripts/`：它们共同定义智能体做什么、按照什么顺序协作，以及每轮结果如何保存。`data/` 提供智能体判断所需的数值依据，`src/` 和 `include/` 是开发智能体实际改进的单元程序。

## 用户视角的输入和输出

技术上的输入是单元物理信息和可信参考矩阵，技术上的输出是实现计算出的单元刚度矩阵及其验证报告。

### 必需输入

1. **项目配置**：单元类型、矩阵尺寸、自由度、数据集、矩阵计算程序和验收阈值。
2. **样本元数据**：一个算例的几何、材料、自由度顺序及文件路径。
3. **可信参考矩阵**：由 Abaqus 或其他可追溯求解器导出的方阵 CSV。
4. **矩阵计算程序**：一个能从终端运行的程序。它读取样本 JSON，计算刚度矩阵，再写出同尺寸 CSV。
5. **数据集清单**：把样本放入互不重叠的 `train`、`validation`、`test`。

### 主要输出

- 实现矩阵 CSV，例如 `data/implementation/s4_train_003_node_down_implementation.csv`；
- 单样本 Markdown 报告；
- `build/verification/dataset-results.json`；
- 编译产物和批量样本报告，默认位于 `build/verification/`；
- 在线迭代的计划、运行记录和检查点，生成在 `build/workflow/`。

## 标准操作流程

### 1. 准备数据

- 填写 `stiffness_agent/config/project.json`；
- 创建样本元数据 JSON；
- 导入可信参考矩阵 CSV；
- 准备一个能从样本 JSON 生成实现矩阵 CSV 的程序；
- 在数据集清单中登记样本。

矩阵 CSV 不带表头，必须是项目配置声明的 `N x N` 方阵，且所有条目为有限数值。参考矩阵必须非零、近似对称并记录来源。

## 更换单元类型时的输入和输出

项目已经包含 S4 的矩阵计算程序。更换为梁、实体或其他单元时，需要另外准备与该单元对应的矩阵计算程序。

这个程序的输入是一个样本 JSON 文件，其中记录：

- 节点坐标；
- 材料参数；
- 厚度、截面或其他单元参数；
- 每节点自由度及其顺序；
- 实现矩阵的输出路径 `implementation_matrix`。

这个程序的输出是 `implementation_matrix` 指定的无表头 CSV。矩阵必须是有限、非零的方阵，并满足：

```text
矩阵阶数 = 节点数 x 每节点自由度数
```

例如，四节点且每节点六个自由度的 S4 输出 `24 x 24` 矩阵；两节点且每节点三个自由度的二维梁输出 `6 x 6` 矩阵。工作流读取这个输出，再与同尺寸的可信参考矩阵比较并生成验证报告。

完整输入和输出示例见 [接入一个 6 x 6 梁单元](用户手册/接入新单元与新增样本.md#完整示例接入一个-6-x-6-梁单元)。

### 2. 执行验证

```bash
python -m stiffness_agent validate-project
python -m stiffness_agent verify --sample <样本元数据.json> --report build/verification/<报告名>.md
python -m stiffness_agent verify-dataset --development
```

开发阶段使用 `--development`，只读取 `train` 和 `validation`。最终验收才运行：

```bash
python -m stiffness_agent verify-dataset --require-test
```

### 3. 检查结果

至少确认：

- 命令退出码为 `0`；
- 实现矩阵尺寸正确、有限、非零；
- 报告中的 Frobenius 相对误差、最大绝对误差和对称性误差可读取；
- `train`、`validation`、`test` 没有重叠；
- 最终验收时测试集哈希锁有效。

## 换一个单元时通常改哪些文件

| 文件或目录 | 用户动作 |
| --- | --- |
| `stiffness_agent/config/project.json` | 修改单元类型、矩阵尺寸、自由度、数据集入口和验收设置 |
| `data/<element>/metadata/*.json` | 新建样本元数据 |
| `data/<element>/reference/*.csv` | 放入可信参考矩阵 |
| `data/datasets/<element>.json` | 维护三个数据集划分 |
| `src/<element>/` 或独立实现目录 | 实现矩阵计算程序 |
| `tests/<element>_tests.*` | 增加物理与回归测试 |

公共框架通常不需要修改。非 S4 单元应提供自己的矩阵计算程序：输入样本 JSON，输出样本指定路径下的刚度矩阵 CSV。不要把 S4 公式硬改成“通用公式”。

## 哪些文件可以删除

| 类型 | 是否可删除 | 影响 |
| --- | --- | --- |
| `build/`、`__pycache__/`、`*.pyc` | 可以 | 下次运行重新生成 |
| `build/workflow/checkpoints/` | 谨慎 | 删除后不能恢复中断的在线运行 |
| `build/workflow/runs/`、`build/workflow/archive/`、`build/workflow/plans/` | 谨慎 | 不影响编译，但会丢失本地审计与计划历史 |
| Abaqus 临时文件，如 `.lck`、`.sta`、`.sim` | 作业结束后通常可以 | 先确认可追溯的 `.mtx`、CSV 和日志已保存 |
| 参考矩阵、样本元数据、数据集清单 | 不可以随意删除 | 样本将不可验证或不可追溯 |
| `.env` | 可以，但不要提交 | 删除后需要重新配置在线接口 |

## 当前 S4 示例

当前仓库配置是 `4 节点 x 每节点 6 自由度 = 24 x 24` 的 Abaqus S4 示例。S4 使用仓库内置的计算程序；其他单元可以让工作流调用用户自己的程序，因此矩阵校验和数据集流程不限定为 `24 x 24`。

S4 的 Abaqus 导出步骤见 [导出 S4 刚度矩阵](abaqus/导出S4刚度矩阵.md)。当前数值状态见 [S4 多样本验证报告](verification/S4多样本Abaqus验证报告.md)。

## 文档组织原则

本手册按常见技术文档分层组织：快速开始用于第一次成功运行；操作指南解决具体任务；参考页集中列出目录、字段和命令；架构页解释设计原因。用户操作文档不再混入实验过程记录，长期结论放在 `docs/verification/`，可重建的本地运行产物放在 `build/workflow/`。
