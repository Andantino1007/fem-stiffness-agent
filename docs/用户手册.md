# 刚度矩阵多智能体工作流用户手册

**适用项目：** `abaqus-s4-multi-agent-workflow`

**适用日期：** 2026-09-06

**面向读者：** 第一次接触本项目、需要运行现有 S4 示例、维护参考样本或接入新单元的工程人员

本手册按照工业软件常见的使用顺序编写：先认识项目和文件，再完成一个可复现的入门算例，然后学习日常操作、扩展配置和故障处理。普通用户完成本手册中的操作，不需要同时翻阅其他文档。

## 手册结构

- **第一部分：认识项目**，说明项目用途、工作流程、文件夹和核心文件之间的关系。
- **第二部分：首次运行教程**，从环境检查开始，完整跑通单样本和开发数据集验证。
- **第三部分：日常使用**，说明如何读报告、运行测试、增加 S4 样本和管理数据集。
- **第四部分：在线智能体**，说明 API、模型、规划、自动迭代和恢复方式。
- **第五部分：扩展与维护**，说明如何接入非 S4 或非 `24 x 24` 矩阵，以及如何排查常见问题。
- **附录**，集中提供命令、配置字段和文件生命周期速查表。

# 第一部分：认识项目

## 第 1 章 项目用途和工作原理

### 1.1 项目解决什么问题

本项目用于比较同一个有限元单元的两份刚度矩阵：

- **参考矩阵**来自 Abaqus 或其他可信求解器，是数值对照基准；
- **实现矩阵**由本项目中的 C++ 程序或外部程序计算，是需要验证和改进的结果。

工作流不会替代有限元求解器，也不会自动猜出任意单元公式。它负责把样本、矩阵程序、参考结果和测试组织成一套可重复执行的验证流程，并计算两份矩阵的差异。

当前仓库内置 Abaqus S4 壳单元示例：

| 项目 | 当前值 |
| --- | --- |
| 节点数 | 4 |
| 每节点自由度 | `ux, uy, uz, rx, ry, rz` |
| 矩阵尺寸 | `24 x 24` |
| 材料 | 各向同性线弹性 |
| 参考求解器 | Abaqus 2024 |
| 训练样本数 | 4 |
| 验证样本数 | 1 |
| 最终测试样本数 | 0，尚未建立最终验收集 |

框架的公共验证部分支持其他方阵尺寸。接入新单元时，需要另外提供该单元的矩阵计算程序、参考样本和数值测试，具体见第 12 章。

### 1.2 一次验证实际做了什么

当用户执行 `python -m stiffness_agent verify` 时，程序按以下顺序工作：

```text
读取项目配置
    ↓
读取样本元数据
    ↓
编译或调用矩阵计算程序
    ↓
根据样本生成实现矩阵 CSV
    ↓
读取可信参考矩阵 CSV
    ↓
检查尺寸、有限性和对称性
    ↓
计算误差并生成报告
    ↓
运行该单元的 C++ 数值测试
```

在线智能体不是验证流程的裁判。它只能提出实验和源码修改，候选修改仍然必须经过本地编译、矩阵比较、训练集和验证集检查后才能保留。参考矩阵不能由智能体生成或修改。

### 1.3 两种容易混淆的“测试”

项目中有两类含义不同的测试：

| 名称 | 含义 | 示例 |
| --- | --- | --- |
| 程序测试 | 检查代码行为是否正确，包括 Python 单元测试和 C++ Catch2 数值测试 | 矩阵是否对称、非法材料是否被拒绝 |
| 数据集 `test` 划分 | 留到最终阶段才读取的独立样本集合 | 未参与训练和调参的新几何样本 |

“程序测试通过”只说明代码没有触发已知回归，不代表矩阵误差已达到目标。“最终测试集通过”才用于评价未见样本上的泛化能力。当前项目的 `test` 划分为空，所以还不能宣称完成最终数值验收。

### 2.2 新用户最常接触的文件

| 文件 | 什么时候使用 | 是否通常修改 |
| --- | --- | --- |
| `stiffness_agent/config/project.json` | 确认当前单元、矩阵尺寸、数据集和验收门槛 | 切换项目或单元时修改 |
| `data/datasets/s4_stiffness.json` | 查看哪些样本属于训练、验证和测试集 | 登记新样本时修改 |
| `data/reference/abaqus/metadata/*.json` | 查看一个样本的几何、材料和矩阵路径 | 新增或修正样本时修改 |
| `data/reference/abaqus/matrices/*.csv` | 保存可信 Abaqus 参考矩阵 | 只在重新导出真实基准时更新 |
| `data/implementation/*.csv` | 保存当前 C++ 实现生成的矩阵 | 由验证命令自动覆盖 |
| `src/fem/s4/S4Stiffness.cpp` | 当前 S4 数值实现 | 开发算法时修改 |
| `build/verification/dataset-results.json` | 查看最近一次数据集验证汇总 | 自动生成，不手工修改 |

### 2.3 哪些目录不能混用

- `data/reference/` 是可信答案区。只允许放真实 Abaqus 导出或经过确认的外部参考数据。
- `data/implementation/` 是被测程序输出区。运行验证时文件会被重新生成。
- `build/` 是临时工作区。可以重新生成，不应作为参考数据来源，也不提交到 Git。
- `tests/infra/` 是第三方 Catch2 源码。普通业务修改不要编辑这里。
- `.env` 保存本机密钥和模型配置，已经被 Git 忽略，禁止提交。

## 第 3 章 核心文件如何关联

项目不是从某个 `.inp` 文件直接开始运行，而是由五类文件共同组成：

```text
项目配置 project.json
    ├── 指向数据集 s4_stiffness.json
    ├── 指向默认样本 sample_001.json
    └── 声明矩阵程序和验收门槛

数据集 s4_stiffness.json
    └── 按 train / validation / test 列出样本元数据路径

样本元数据 sample_001.json
    ├── 保存节点、材料和厚度
    ├── 指向参考矩阵 CSV
    └── 指向实现矩阵 CSV

参考矩阵 CSV ← Abaqus .inp、.mtx 和日志提供来源证据
实现矩阵 CSV ← C++ 矩阵程序根据样本元数据生成
```

### 3.1 用 `sample_001` 看完整数据链

1. `stiffness_agent/config/project.json` 把 `primary_sample` 设为 `data/reference/abaqus/metadata/sample_001.json`。
2. `sample_001.json` 保存四个节点坐标、材料、厚度和自由度顺序。
3. 元数据的 `reference_matrix` 指向 `data/reference/abaqus/matrices/sample_001_reference.csv`。
4. 元数据的 `implementation_matrix` 指向 `data/implementation/sample_001_implementation.csv`。
5. 验证命令调用 S4 C++ 程序，覆盖生成第 4 步的实现矩阵。
6. 工作流比较两份 CSV，把误差写入用户指定的 Markdown 报告。

这里最重要的规则是：**参考矩阵和实现矩阵必须来自两条独立路径。** 不得把 C++ 计算结果复制到参考目录，也不得用旧样本矩阵冒充新几何的 Abaqus 结果。

### 3.2 `train`、`validation` 和 `test`

| 划分 | 用途 | 自动迭代时是否可见 |
| --- | --- | --- |
| `train` | 提供详细误差，用于定位和改进算法 | 可见 |
| `validation` | 检查修改是否只适配训练样本 | 可见，但不能作为目标样本反复调参 |
| `test` | 最终独立验收，带文件哈希锁 | 开发模式不读取 |

同一个元数据文件不能同时出现在两个划分中。开发阶段使用 `--development`，保证程序不读取锁定测试集。

# 第二部分：首次运行教程

本部分的目标是让第一次接触项目的用户完成一条完整流程。请按章节顺序操作，不需要先配置模型 API，也不需要安装 Abaqus。

## 第 4 章 准备运行环境

### 4.1 前置条件

离线验证需要：

- Python 3.10 或更高版本；
- 一个支持 C++17 的编译器；
- 编译器能通过 `c++` 命令调用，或已在环境变量 `CXX` 中指定；
- 当前终端可以访问仓库目录。

Abaqus 只在创建或重新导出参考矩阵时需要。运行仓库中已有样本不调用 Abaqus，也不调用在线模型。

### 4.2 进入项目目录

在 PowerShell 中执行：

```powershell
Set-Location D:\intern\Kagent
```

在 WSL 中执行：

```bash
cd /mnt/d/intern/Kagent
```

后续所有命令都在仓库根目录执行。可以用下面的命令确认位置：

```powershell
Get-Location
Test-Path stiffness_agent/config/project.json
```

第二条命令应输出 `True`。

### 4.3 检查 Python 和编译器

```powershell
python --version
c++ --version
```

如果 `python` 不存在，安装 Python 后重新打开终端。如果 `c++` 不存在，有三种选择：

1. 安装 MinGW-w64，并把编译器目录加入 `PATH`；
2. 安装 LLVM，把 `CXX` 设置为 `clang++`；
3. 在 WSL Ubuntu 中运行本项目。

例如临时使用 Clang：

```powershell
$env:CXX = "clang++"
```

项目的 `verify` 和 `verify-dataset` 会直接调用这里确认的编译器。仅安装 Visual Studio 但没有可用的 `c++` 或 `CXX` 命令时，验证仍会报告找不到编译器。

### 4.4 安装 Python 依赖

```powershell
python -m pip install -r requirements.txt
```

建议在 Conda 或 `venv` 环境中安装。项目原有 Conda 环境可用时，先执行：

```powershell
conda activate stiffness-multiagent
```

### 4.5 检查项目配置

```powershell
python -m stiffness_agent check
```

这个命令会检查：

- `project.json` 字段是否完整且相互一致；
- 数据集和主样本路径是否存在；
- LangGraph 和 SQLite checkpoint 依赖是否可用；
- 编排图能否建立。

它不会编译 C++、不会生成矩阵、不会调用模型 API。成功时进程退出码为 `0`，终端会显示项目配置和 LangGraph 环境检查通过。

## 第 5 章 跑通第一个 S4 样本

### 5.1 本教程使用哪些输入

本次验证使用仓库自带的单位正方形样本：

| 内容 | 文件 |
| --- | --- |
| 样本参数 | `data/reference/abaqus/metadata/sample_001.json` |
| Abaqus 参考矩阵 | `data/reference/abaqus/matrices/sample_001_reference.csv` |
| S4 C++ 实现 | `src/fem/s4/` |
| C++ 数值测试 | `tests/s4_stiffness_tests.cpp` |

运行前不需要打开或编辑这些文件。

### 5.2 执行单样本验证

PowerShell：

```powershell
python -m stiffness_agent verify --sample data/reference/abaqus/metadata/sample_001.json --report build/verification/sample_001-report.md
```

Bash 或 WSL：

```bash
python3 -m stiffness_agent verify \
  --sample data/reference/abaqus/metadata/sample_001.json \
  --report build/verification/sample_001-report.md
```

### 5.3 命令执行期间会发生什么

1. 读取当前 S4 项目配置和 `sample_001.json`。
2. 用 C++17 编译 `build/verification/s4_stiffness_cli` 和 `s4_stiffness_tests`。
3. 运行矩阵程序，生成或覆盖 `data/implementation/sample_001_implementation.csv`。
4. 比较实现矩阵和 Abaqus 参考矩阵。
5. 写出 `build/verification/sample_001-report.md`。
6. 运行 7 个 Catch2 C++ 数值测试。

成功时，终端末尾应出现：

```text
Element matrix verification completed.
Report: build/verification/sample_001-report.md
```

如果在编译步骤失败，先看第 13.2 节。不要跳过编译后手工制作实现矩阵。

### 5.4 检查生成结果

```powershell
Get-Item build/verification/sample_001-report.md
Get-Content build/verification/sample_001-report.md
```

报告应包含四个核心指标：

- `Frobenius relative error`
- `max absolute error`
- `max relative entry error`
- `symmetry error`

当前基线的 `sample_001` Frobenius 相对误差约为 `0.0410265`。项目目标为 `0.01`，因此当前实现能够完整运行并通过回归测试，但尚未达到 1% 数值目标。

### 5.5 本步骤修改了哪些文件

| 文件 | 变化 |
| --- | --- |
| `data/implementation/sample_001_implementation.csv` | 由 C++ 程序重新生成 |
| `build/verification/s4_stiffness_cli*` | 新建或覆盖编译产物 |
| `build/verification/s4_stiffness_tests*` | 新建或覆盖测试程序 |
| `build/verification/sample_001-report.md` | 新建验证报告 |

参考矩阵 `data/reference/abaqus/matrices/sample_001_reference.csv` 不会被验证命令修改。

## 第 6 章 跑通开发数据集

### 6.1 为什么还要运行数据集验证

单样本只能证明程序在一个几何上可运行。开发数据集还包含远点梯形、长方形、非共面翘曲四边形和斜平行四边形，用于检查修改在不同几何上的表现。

### 6.2 执行命令

```powershell
python -m stiffness_agent verify-dataset --development
```

`--development` 明确规定只读取 `train` 和 `validation`，不会读取 `test`。当前命令会：

1. 编译一次 S4 矩阵程序和 Catch2 测试程序；
2. 依次生成 4 个训练样本的实现矩阵；
3. 生成 1 个验证样本的实现矩阵；
4. 为每个样本生成单独报告；
5. 汇总各划分的平均误差和最差样本；
6. 运行一次 C++ 数值测试。

成功时终端末尾应类似：

```text
Dataset verification completed.
Train: 4 sample(s), worst error=...
Validation: 1 sample(s), worst error=...
Test: skipped (development scope never evaluates the locked test set)
Result: build/verification/dataset-results.json
```

### 6.3 输出文件

```text
build/verification/
├── dataset-results.json
└── dataset-reports/
    ├── train/                   每个训练样本的报告
    └── validation/              每个验证样本的报告
```

当前基线结果为：训练集平均 Frobenius 相对误差约 `0.214598875`，最差训练样本为 `s4_train_003_node_down`，误差约 `0.357604`；验证样本误差约 `0.207454`。这些值用于确认是否发生回归，不代表已经达到最终验收目标。

### 6.4 首次运行完成的判断标准

完成以下检查后，说明本机离线环境已经可以使用：

- `python -m stiffness_agent check` 返回成功；
- 单样本命令生成报告；
- 数据集命令识别出 4 个训练样本和 1 个验证样本；
- C++ Catch2 显示 7 个测试用例、621 个断言通过；
- `build/verification/dataset-results.json` 存在；
- 终端没有编译错误或矩阵读取错误。

# 第三部分：日常使用

## 第 7 章 读取验证结果

### 7.1 四个核心指标

| 指标 | 回答的问题 | 读取方式 |
| --- | --- | --- |
| `frobenius_relative_error` | 整体矩阵与参考矩阵相差多少 | 当前主要数值指标，越小越好 |
| `max_absolute_error` | 最大的单个条目差值是多少 | 结合刚度量级判断局部大误差 |
| `max_relative_entry_error` | 某个条目的相对差最大是多少 | 参考值接近零时会被放大，不能单独用于结论 |
| `symmetry_error` | 实现矩阵是否接近对称 | 当前门槛为 `1e-12`，越接近零越好 |

Frobenius 相对误差把所有条目综合为一个无量纲比值，适合比较不同迭代。最大绝对误差用于定位最严重的单个条目。对称性通过只说明矩阵结构合理，不说明数值已经与 Abaqus 一致。

### 7.2 单样本报告和数据集结果的区别

- 单样本 Markdown 报告回答“这个样本的误差是多少”。
- `dataset-results.json` 回答“每个划分有多少样本、平均误差是多少、最差样本是谁”。

数据集结果的主要层级如下：

```text
project_id
element_type
matrix_dimensions
evaluation_scope
splits
    train
        samples
        summary
    validation
        samples
        summary
    test
        samples
        summary
validation_ready
test_ready
test_lock_valid
final_evaluation_ready
```

查看汇总：

```powershell
Get-Content -Raw build/verification/dataset-results.json
```

### 7.3 如何判断一次修改是否值得保留

算法修改至少应满足以下条件：

1. C++ 编译和 Catch2 测试通过；
2. Python 工作流测试通过；
3. 目标训练样本的 Frobenius 相对误差下降；
4. 其他训练样本没有不可接受的退化；
5. 验证集误差没有超过项目配置允许的回归量；
6. 对称性误差仍在门槛内；
7. 参考矩阵和样本元数据未被算法修改。

不要用“命令退出码为 0”代替数值结论。退出码为 0 说明流程完成，最终是否达标还要对照 `project.json` 中的 `acceptance.target_error` 和独立测试集结果。

## 第 8 章 常用运行任务

### 8.1 只检查项目配置

```powershell
python -m stiffness_agent validate-project
```

适用于修改 `project.json` 后快速检查字段、尺寸、自由度和适配器声明。该命令不编译程序，也不生成矩阵。

### 8.2 验证任意一个已登记样本

```powershell
python -m stiffness_agent verify --sample data/reference/abaqus/metadata/s4_train_003_node_down.json --report build/verification/s4_train_003_node_down-report.md
```

把 `--sample` 替换为目标元数据路径，把 `--report` 替换为希望保存的报告路径。建议把临时报告写入 `build/verification/`，避免覆盖 `docs/verification/` 中已经归档的正式报告。

### 8.3 运行全部 Python 测试

```powershell
python -m unittest discover -s tests -p "*_tests.py" -v
```

这些测试检查命令行解析、项目配置、矩阵转换、API 客户端、智能体补丁安全规则和 LangGraph 路由。测试使用模拟接口，不会发送真实在线请求。

### 8.4 运行 C++ 数值测试

最简单的方式是执行：

```powershell
python -m stiffness_agent verify
```

该命令会自动编译并运行 `tests/s4_stiffness_tests.cpp`。当前测试覆盖矩阵尺寸、各物理分量对称性、有限数值、刚体平移、非共面翘曲样本和非法材料参数。

### 8.5 修改 S4 算法后的推荐顺序

修改 `src/fem/s4/S4Stiffness.cpp` 后按以下顺序执行：

```powershell
python -m stiffness_agent check
python -m stiffness_agent verify --report build/verification/sample_001-report.md
python -m stiffness_agent verify-dataset --development
python -m unittest discover -s tests -p "*_tests.py" -v
git diff --check
git status --short
```

然后检查 `dataset-results.json`，确认目标样本改善且验证集没有退化，再决定是否提交。

### 8.6 验证后实现矩阵出现 Git 修改

这是正常现象。验证命令会按当前编译器和算法重新写入 `data/implementation/*.csv`。先查看差异：

```powershell
git diff -- data/implementation
```

如果这些文件是本次算法修改应产生的新结果，应与源码和报告一起审查。如果只是换平台导致最后几位浮点文本变化，并且运行前确认工作树没有用户修改，可以逐文件恢复。不得用同样方式恢复 `data/reference/` 中的参考矩阵。

## 第 9 章 增加一个 S4 参考样本

本章适用于增加新的 S4 几何、材料或厚度样本。不要覆盖现有样本，每个新样本使用唯一 `sample_id`。

### 9.1 操作前准备

准备以下信息：

- 唯一样本名，例如 `s4_train_004_thick_plate`；
- 4 个节点坐标和固定的节点顺序；
- 材料参数和厚度；
- 计划登记的划分：`train`、`validation` 或 `test`；
- 安装了 Abaqus 的运行环境。

推荐文件名：

```text
data/reference/abaqus/input_decks/<sample_id>_matrix_export.inp
data/reference/abaqus/raw_matrices/<sample_id>_STIF1.mtx
data/reference/abaqus/matrices/<sample_id>_reference.csv
data/reference/abaqus/metadata/<sample_id>.json
data/reference/abaqus/logs/<sample_id>.msg
data/implementation/<sample_id>_implementation.csv
```

### 9.2 创建 Abaqus 输入文件

复制一个已有矩阵导出输入文件，只修改新样本需要的节点、材料、厚度和作业名称。保留以下矩阵导出关键词：

```text
*STEP, NAME=EXPORT_STIFFNESS
*MATRIX GENERATE, STIFFNESS
*MATRIX OUTPUT, STIFFNESS, FORMAT=COORDINATE
*END STEP
```

当前 S4 约定为节点 `1, 2, 3, 4`，每节点自由度顺序为 `ux, uy, uz, rx, ry, rz`。节点顺序或自由度顺序变化会导致矩阵行列含义变化，不能只靠对称性检查发现。

### 9.3 运行真实 Abaqus

在 Abaqus Command 中进入仓库根目录并执行：

```bat
abaqus job=<sample_id> input=data\reference\abaqus\input_decks\<sample_id>_matrix_export.inp interactive
```

作业结束后检查 `.msg`、`.dat` 或 `.log`：

- 作业必须正常完成；
- `ERROR` 数量必须为 0；
- 记录所有 `WARNING`，不要仅记录数量；
- 确认日志中存在矩阵输出信息；
- 保存 Abaqus 版本和实际作业名。

如果 Abaqus 直接生成 `*_STIF1.mtx`，把它复制到 `raw_matrices/`。如果只生成 `<job>_X1.sim`，执行：

```bat
abaqus mtxasm job=<job>_X1 text
```

然后找到生成的 `*_STIF-1.mtx`，按统一文件名保存到 `raw_matrices/`。不要用 C++ 实现矩阵代替此步骤。

### 9.4 把 `.mtx` 转成参考 CSV

```powershell
python scripts/abaqus/convert_abaqus_mtx_to_csv.py data/reference/abaqus/raw_matrices/<sample_id>_STIF1.mtx data/reference/abaqus/matrices/<sample_id>_reference.csv
```

转换脚本接受一个输入 `.mtx` 和一个输出 CSV。它支持 Abaqus 坐标条目，并会补齐缺失的对称项。转换成功后仍要确认：

- CSV 恰好 24 行，每行 24 个数；
- 所有数值有限；
- 矩阵不是全零；
- 对称性误差小于 `1e-10`；
- 原始 `.mtx` 的条目数已经记录。

后续 `register-sample` 会再次执行尺寸、非零、有限性和对称性检查。

### 9.5 创建完整样本元数据

从 `data/templates/sample-meta.example.json` 或相近 S4 样本复制，至少写明以下内容：

```json
{
  "sample_id": "s4_train_004_thick_plate",
  "element_type": "Abaqus S4",
  "node_order": "counterclockwise",
  "dof_order_per_node": ["x", "y", "z", "rx", "ry", "rz"],
  "nodes": [
    {"id": 1, "coord": [0.0, 0.0, 0.0]},
    {"id": 2, "coord": [1.0, 0.0, 0.0]},
    {"id": 3, "coord": [1.0, 1.0, 0.0]},
    {"id": 4, "coord": [0.0, 1.0, 0.0]}
  ],
  "material": {
    "type": "isotropic_linear_elastic",
    "E": 210000000000.0,
    "nu": 0.3
  },
  "section": {"thickness": 0.02},
  "reference_matrix_source": {
    "status": "real_abaqus_export",
    "solver": "Abaqus 2024",
    "job": "s4_train_004_thick_plate",
    "method": "MATRIX GENERATE -> STIF1.mtx -> CSV",
    "source_mtx": "data/reference/abaqus/raw_matrices/s4_train_004_thick_plate_STIF1.mtx",
    "parsed_entries": 376,
    "error_count": 0,
    "warning_count": 0,
    "log": "data/reference/abaqus/logs/s4_train_004_thick_plate.msg"
  },
  "reference_matrix": "data/reference/abaqus/matrices/s4_train_004_thick_plate_reference.csv",
  "implementation_matrix": "data/implementation/s4_train_004_thick_plate_implementation.csv"
}
```

示例中的坐标、厚度、条目数和日志信息必须替换成真实作业数据。`status` 只能是 `real_abaqus_export` 或经过人工确认的 `verified_external_reference`。

### 9.6 登记样本

登记到训练集：

```powershell
python -m stiffness_agent register-sample --meta data/reference/abaqus/metadata/<sample_id>.json --split train
```

也可以把 `--split` 改为 `validation` 或 `test`。登记命令会检查：

- `sample_id` 是否存在且未重复；
- `element_type` 是否与当前项目一致；
- 参考来源状态是否可信；
- 参考矩阵是否存在、尺寸正确、非零、有限且近似对称；
- 元数据是否已出现在其他划分中。

登记到 `test` 时，程序会同时重建 `data/datasets/test-lock.json`，记录测试元数据和参考矩阵的 SHA-256 哈希。

### 9.7 验证新样本并检查提交内容

```powershell
python -m stiffness_agent verify --sample data/reference/abaqus/metadata/<sample_id>.json --report build/verification/<sample_id>-report.md
python -m stiffness_agent verify-dataset --development
python -m unittest discover -s tests -p "*_tests.py" -v
git diff --check
git status --short
```

提交前应包含新 `.inp`、真实 `.mtx`、精简日志、参考 CSV、元数据、实现 CSV和数据集清单。不要提交 `.sim`、`.odb`、`.lck`、求解器缓存或与该样本无关的大型运行文件。

## 第 10 章 管理数据集和最终验收

### 10.1 查看当前划分

```powershell
Get-Content -Raw data/datasets/s4_stiffness.json
```

数据集只保存元数据路径，不直接保存节点和矩阵。修改样本内容时要更新元数据指向的真实产物，不能仅改清单名称。

### 10.2 开发验证

```powershell
python -m stiffness_agent verify-dataset --development
```

这是日常开发的默认命令。它读取训练集和验证集，明确跳过测试集。

### 10.3 检查测试集锁

测试样本登记完成后执行：

```powershell
python -m stiffness_agent check-test-lock
```

如果元数据、参考矩阵或测试清单在锁定后发生变化，检查会失败。此时应先确认变化是否经过授权并能追溯，而不是直接删除锁文件。

### 10.4 最终验收

```powershell
python -m stiffness_agent verify-dataset --require-test
```

只有同时满足以下条件时，`final_evaluation_ready` 才为 `true`：

- 验证集非空；
- 测试集非空；
- 测试集哈希锁有效；
- 所有样本计算和单元测试完成。

当前仓库测试集为空，所以执行 `--require-test` 会以非零退出码结束。这是数据准备状态，不是程序崩溃。

# 第四部分：在线智能体

在线智能体用于在既有参考数据和测试门禁下提出算法改进。第一次使用项目时，先完成第二部分的离线验证。离线流程未通过时，不要启动自动迭代。

## 第 11 章 配置和运行在线智能体

### 11.1 创建本机配置

在仓库根目录复制示例：

```powershell
Copy-Item .env.example .env
```

然后用文本编辑器修改 `.env`。它只保存在本机，不能提交到 Git。

| 字段 | 用户需要填写什么 |
| --- | --- |
| `OPENAI_API_KEY` | 当前服务商提供的 API 密钥 |
| `OPENAI_MODEL` | 服务商实际开放的模型标识 |
| `OPENAI_BASE_URL` | API 根地址，兼容网关通常以 `/v1` 结尾 |
| `OPENAI_API_STYLE` | 不确定时使用 `auto`；也可指定 `responses` 或 `chat_completions` |
| `OPENAI_TIMEOUT_SECONDS` | 单次请求超时秒数 |
| `OPENAI_MAX_RETRIES` | 临时网络错误的重试次数 |
| `OPENAI_MAX_OUTPUT_TOKENS` | 单次响应最大输出长度 |
| `OPENAI_REASONING_EFFORT` | 服务支持时使用的推理强度 |

模型名称必须以接口实际返回为准。配置文件中的示例值只是占位或本机曾用设置，不保证其他账号可用。

### 11.2 检查接口

```powershell
python -m stiffness_agent api-check
```

该命令会发送一个最小真实请求，检查密钥、基础地址、模型名称和接口格式。它与 `check` 不同：

| 命令 | 是否联网 | 用途 |
| --- | --- | --- |
| `python -m stiffness_agent check` | 否 | 检查本地配置、依赖和编排图 |
| `python -m stiffness_agent api-check` | 是 | 检查真实 API、模型和网关 |

只有 `api-check` 成功后，才继续运行 `replan` 或 `run`。

### 11.3 建立新的规划目标

当单元类型、数据集、算法方向或验收目标发生变化时，先重置规划代次：

```powershell
python -m stiffness_agent reset-plan --reason "开始改进 S4 翘曲单元的局部坐标和横向剪切"
```

`--reason` 应说明为什么旧规划不再适用。该命令会归档当前活动规划记忆，不会修改有限元源码。

然后只运行基线验证和 Planner：

```powershell
python -m stiffness_agent replan
```

先检查生成的规划是否围绕当前数据和允许修改的源码，再启动自动迭代。

### 11.4 启动自动迭代

运行 3 轮：

```powershell
python -m stiffness_agent run --max-iterations 3
```

显式指定目标误差：

```powershell
python -m stiffness_agent run --max-iterations 20 --target-error 0.01
```

每轮大致执行：

```text
Planner 选择实验
    ↓
Theory 分析可能的有限元原因
    ↓
Developer 生成限定路径内的补丁
    ↓
本地补丁安全检查和试应用
    ↓
编译、单样本验证、数据集验证和测试
    ↓
Reviewer 判断是否接受
    ↓
无改善则恢复候选修改，有改善才保留
```

模型不能直接决定补丁通过。`agent.allowed_patch_paths` 限定可修改文件，参考矩阵路径不在白名单内。

### 11.5 查看运行记录

每次运行会生成唯一编号，例如 `run-20260906-153000`，主要文件位于：

```text
build/workflow/runs/<run_id>/
├── state.json                  当前机器可读状态
├── langgraph-status.json       图运行状态
├── summary.md                  人工阅读的运行汇总
└── iteration-01/               每轮规划、补丁、日志和验证结果
```

这些记录用于本机诊断和恢复，默认不提交。删除 `build/workflow/` 会同时删除检查点、运行历史和跨轮实验记忆。

### 11.6 中断后恢复

接口超时或终端中断后，使用终端打印的运行编号：

```powershell
python -m stiffness_agent resume <run_id>
```

只有检查点仍存在时才能恢复。切换了源码基线、项目配置或数据集后，不建议恢复旧运行，应建立新的规划代次。

### 11.7 如何理解运行退出状态

- 达到目标或至少接受一轮有效改进时，命令正常结束；
- 没有候选通过时，候选源码会被恢复，这不代表参考数据丢失；
- 接口节点失败时，终端会给出恢复命令；
- 最终结论仍应查看 `summary.md`、数据集结果和 Git 差异，不能只看模型文字。

# 第五部分：扩展与维护

## 第 12 章 接入非 S4 或非 24×24 单元

### 12.1 先判断是“新增样本”还是“新增单元”

| 需求 | 应采用的方式 |
| --- | --- |
| 节点坐标、材料或厚度变化，但仍是 4 节点 S4 | 按第 9 章增加 S4 样本 |
| 自由度数量变化 | 建立新的单元项目配置和矩阵程序 |
| 节点数变化 | 建立新的单元项目配置和矩阵程序 |
| 矩阵从 `24 x 24` 变为其他方阵 | 使用通用 `command` 适配器 |
| 仍为 S4，但只想改算法实现 | 保留 `builtin_s4`，修改 S4 源码和测试 |

公共比较器支持项目配置声明的任意**方阵**，例如 `6 x 6`、`8 x 8` 或 `60 x 60`。当前契约不支持非方阵，因为刚度矩阵验证按方阵、对称性和统一自由度编号设计。

### 12.2 新单元需要准备的五项内容

以两节点平面梁、每节点 3 个自由度、`6 x 6` 矩阵为例：

1. **项目配置**：声明节点数、自由度和 `6 x 6` 尺寸；
2. **矩阵程序**：读取样本 JSON，计算梁刚度矩阵并写出 CSV；
3. **参考样本**：来自可信求解器的 `6 x 6` 参考矩阵；
4. **数据集**：分别登记训练、验证和最终测试样本；
5. **程序测试**：检查刚体模态、对称性、材料边界和已知解析结果。

推荐独立目录，不要把新单元源码放进 `src/fem/s4/`：

```text
src/fem/beam2/
include/fem/beam2/
src/cli/beam2_stiffness_cli.cpp
tests/beam2_stiffness_tests.cpp
data/beam2/metadata/
data/beam2/reference/
data/beam2/implementation/
data/datasets/beam2.json
```

### 12.3 创建项目配置

从 `stiffness_agent/config/project.example.json` 复制并修改。一个 `6 x 6` 梁单元配置可以写成：

```json
{
  "schema_version": 1,
  "project_id": "beam2-stiffness",
  "element_type": "BEAM2",
  "matrix_dimensions": [6, 6],
  "node_count": 2,
  "dof_labels_per_node": ["ux", "uy", "rz"],
  "diagnostic_groups": {
    "axial": ["ux"],
    "bending": ["uy", "rz"]
  },
  "dataset": "data/datasets/beam2.json",
  "primary_sample": "data/beam2/metadata/train_001.json",
  "reference_generation_methods": ["external_solver"],
  "adapter": {
    "kind": "command",
    "build_command": ["cmake", "--build", "build/beam2"],
    "evaluate_command": ["build/beam2/beam2_stiffness_cli", "{sample}"],
    "test_command": ["build/beam2/beam2_stiffness_tests"]
  },
  "agent": {
    "allowed_patch_paths": ["src/fem/beam2/Beam2Stiffness.cpp"],
    "test_paths": ["tests/beam2_stiffness_tests.cpp"],
    "experiment_classes": ["axial", "bending", "dof_mapping"]
  },
  "acceptance": {
    "target_error": 0.01,
    "min_frobenius_absolute_drop": 1e-06,
    "min_frobenius_relative_drop": 0.0001,
    "max_symmetry_error": 1e-12,
    "max_absolute_error_regression": 0.01,
    "max_non_target_block_regression": 0.05,
    "max_validation_error_regression": 0.0
  }
}
```

必须满足：

```text
矩阵阶数 = node_count × 每节点自由度数量
```

上例中 `2 × 3 = 6`。`diagnostic_groups` 中使用的自由度名称必须来自 `dof_labels_per_node`。

### 12.4 `command` 适配器的具体含义

`command` 不是有限元算法，也不是要求用户编写某种“适配器类”。它只是把现有的三个终端步骤告诉工作流：

1. `build_command`：先执行什么命令来编译矩阵程序；
2. `evaluate_command`：给定一个样本后，执行什么程序生成实现矩阵；
3. `test_command`：矩阵生成后，执行什么命令运行该单元测试。

对于上面的梁示例，一次 `verify` 相当于依次执行：

```powershell
cmake --build build/beam2
build/beam2/beam2_stiffness_cli data/beam2/metadata/train_001.json
build/beam2/beam2_stiffness_tests
```

其中 `{sample}` 会被工作流替换成当前样本 JSON 的实际路径。矩阵程序应完成两件事：

1. 从命令行读取样本元数据路径；
2. 把计算结果写到元数据 `implementation_matrix` 指定的 CSV。

程序不需要自己计算误差或写 Markdown 报告。`evaluate_command` 成功后，公共验证层会读取参考 CSV 和实现 CSV，检查配置声明的尺寸并生成报告。

### 12.5 新单元样本契约

```json
{
  "sample_id": "beam2_train_001",
  "element_type": "BEAM2",
  "parameters": {
    "length": 2.0,
    "E": 210000000000.0,
    "area": 0.01,
    "inertia": 8.333333333e-6
  },
  "reference_matrix_source": {
    "status": "verified_external_reference",
    "solver": "可信求解器名称",
    "job": "beam2_reference_001"
  },
  "reference_matrix": "data/beam2/reference/beam2_train_001.csv",
  "implementation_matrix": "data/beam2/implementation/beam2_train_001.csv"
}
```

`parameters` 的内部字段由新矩阵程序解释。公共层只要求 `sample_id`、`element_type`、可信来源、参考矩阵路径和实现矩阵路径。

### 12.6 验证新单元

把新配置作为活动项目配置后，先运行：

```powershell
python -m stiffness_agent validate-project
python -m stiffness_agent verify --sample data/beam2/metadata/train_001.json --report build/verification/beam2_train_001-report.md
python -m stiffness_agent verify-dataset --development
python -m unittest discover -s tests -p "*_tests.py" -v
```

当前 `validate-project` 和样本登记默认读取 `stiffness_agent/config/project.json`，所以正式切换项目时应先备份 S4 配置，再把新配置放到该路径。`verify` 和 `verify-dataset` 虽然支持 `--project` 指定其他配置，但登记命令仍以活动配置为准。

## 第 13 章 故障处理

排错时先处理终端中出现的第一条错误。后续错误通常是前一步失败引起的连锁结果。

### 13.1 `check` 报项目配置错误

常见原因：

- `matrix_dimensions` 不是方阵；
- 矩阵阶数不等于节点数乘每节点自由度数；
- 数据集或主样本路径不存在；
- 诊断组引用了未声明的自由度；
- `adapter.kind` 不是 `builtin_s4` 或 `command`；
- `command` 缺少生成矩阵所需的 `evaluate_command`。

处理方法：对照附录 B 逐项修正 `project.json`，然后重新运行 `validate-project`。

### 13.2 终端显示 `Command not found: c++`

原因是验证器无法启动 C++17 编译器。先确认：

```powershell
c++ --version
```

如果实际编译器是 Clang：

```powershell
$env:CXX = "clang++"
python -m stiffness_agent verify --report build/verification/sample_001-report.md
```

Windows 编译环境难以配置时，可以在 WSL 中进入 `/mnt/d/intern/Kagent` 后运行相同的 Python 命令。

### 13.3 报告提示矩阵尺寸不正确

检查三处是否一致：

1. `project.json` 的 `matrix_dimensions`；
2. 参考 CSV 的行列数；
3. 矩阵程序输出 CSV 的行列数。

CSV 不允许表头、行名或空的尾列。S4 必须是 24 行、每行 24 个数值。

### 13.4 报告提示参考矩阵为空或不对称

不要降低校验门槛掩盖问题。检查：

- `.mtx` 是否取自正确作业；
- 是否把多个增量或多个矩阵文件误合并；
- Abaqus 是否只输出一个三角区，转换脚本是否正确补齐；
- 自由度编号是否按 1-based Abaqus 格式解析；
- 输出文件是否被旧运行或手工编辑覆盖。

修复来源或转换过程后重新生成 CSV，并在元数据中记录新的条目数和导出方法。

### 13.5 数据集登记被拒绝

终端会在 `Sample registration rejected` 后说明原因。常见情况包括样本 ID 重复、元数据已经登记、`element_type` 不一致、参考来源状态不可信或参考矩阵无效。应修正元数据和真实产物，不要手工绕过登记检查。

### 13.6 `--require-test` 返回失败

先查看 `dataset-results.json` 中：

- `test_ready`
- `test_lock_valid`
- `test_lock_message`
- `final_evaluation_ready`

测试集为空时，需要创建独立参考样本并登记到 `test`。哈希变化时，需要确认变化是否合理，再重新登记或重建受控锁，不能把开发样本临时复制进测试集。

### 13.7 `api-check` 失败

按顺序检查：

1. `.env` 是否位于仓库根目录；
2. `OPENAI_API_KEY` 是否仍为示例占位值；
3. `OPENAI_BASE_URL` 是否是当前服务的 API 根地址；
4. 地址是否缺少 `/v1`；
5. `OPENAI_MODEL` 是否是账号实际可用的模型标识；
6. 网关是否支持所选 `OPENAI_API_STYLE`；
7. 超时和网络代理是否允许访问服务。

使用 `auto` 时客户端可以在支持的接口格式之间回退，但不能修复错误密钥、错误地址或不存在的模型。

### 13.8 Windows 终端中文乱码

PowerShell 中可先执行：

```powershell
chcp 65001
$env:PYTHONUTF8 = "1"
```

重新打开终端后再运行命令。乱码只影响显示时，也要通过退出码和生成文件判断实际结果；如果路径包含中文并导致读取失败，优先使用仓库内已有的 ASCII 目录路径。

### 13.9 Abaqus 只生成 `.sim`，没有 `.mtx`

确认输入文件使用 `*MATRIX GENERATE` 和 `*MATRIX OUTPUT, STIFFNESS, FORMAT=COORDINATE`，然后运行：

```bat
abaqus mtxasm job=<job>_X1 text
```

如果仍失败，保留 `.msg` 和 `.dat`，确认 Abaqus 版本、许可证和命令格式。反力法是备用导出路径，具体脚本位于 `scripts/abaqus/`，但元数据必须明确标注采用了哪一种方法。

### 13.10 哪些文件可以清理

| 文件或目录 | 是否可直接重建 | 注意事项 |
| --- | --- | --- |
| `build/verification/` | 是 | 删除后重新运行验证即可 |
| `__pycache__/`、`*.pyc` | 是 | Python 缓存 |
| `build/workflow/runs/` | 可以，但会丢历史 | 删除后不能查看旧轮次 |
| `build/workflow/checkpoints/` | 可以，但会丢恢复点 | 删除后不能 `resume` |
| `data/implementation/` | 可由程序重建 | Git 中的基线文件不要无意删除 |
| `data/reference/` | 否 | 保存可信基准和来源证据 |
| `.env` | 可重新配置 | 含密钥，不能提交或分享 |
